# 系统架构

VibeStory 是用来展示任务状态机、幂等、作用域、版本与来源追溯的原型。[创作流程](workflow.md)说明用户如何操作，[本地开发与验收](development.md)说明如何运行和验证。

| 模块 | 职责 |
| --- | --- |
| [apps/web](../apps/web/) | React / TypeScript 工作台，负责编辑、审阅和状态展示。启动时 API 不可用会进入独立的离线演示；联机后请求失败显示错误。 |
| [apps/api](../apps/api/) | Java 21 / Spring Boot。按业务聚合组织，负责会话、授权、事务、任务执行和媒体访问。PostgreSQL 16 保存业务事实，Flyway 管理迁移。 |
| [apps/agent](../apps/agent/) · [skills](../skills/README.md) | 受控工具的类型契约与 Markdown Skill 文件库；实际 Agent 运行和业务调用由 API 模块执行。 |
| [apps/mcp](../apps/mcp/) | Codex 可通过本地 STDIO 调用的独立入口，访问相同的工作台 API。 |
| [packages/contracts](../packages/contracts/README.md) | 生成的 OpenAPI、TypeScript 类型和内部 MQ 通知 schema。 |

## 任务、批次与故障恢复

[任务模块](../apps/api/src/main/java/com/vibestory/task/)在提交时校验作用域、确认状态和版本，冻结实际输入。重复请求复用原结果；相同请求键提交不同内容会冲突。主动生成新版本使用新的请求身份。整集批次保存逐镜受理、复用或阻塞结果，成员关联已有任务状态。浏览器刷新后可重新查询。

默认 Worker 从数据库领取任务，以短事务与租约保护并发领取、心跳和结果写回。任务、执行尝试与指标分别记录。Mock 执行中断后可重领；真实视频已有外部任务号时复用原 attempt 查询或下载；缺少可恢复的外部身份且结果未知时标记 UNKNOWN，重试需要显式确认。已知失败仍按原任务重试。外部生成不承诺 exactly-once。

| 机制 | 承担的职责 |
| --- | --- |
| PostgreSQL | 保存任务、尝试、批次、输入快照和派发状态，是状态与恢复依据。 |
| [RabbitMQ 与事务 Outbox](archive/backend-phase7.md) | 入队状态和 Outbox 在同一数据库事务提交。Relay 收到发布确认且无不可路由退回后标记发送；Worker 领取事务提交后 ACK，重复通知经任务状态、派发轮次和租约去重。毒消息和超预算失败有持久化记录，派发暂停后显式恢复。 |
| [Redis 共享准入](archive/backend-phase8.md) | 可选，仅 RabbitMQ 模式启用。Lua 令牌桶限制新生成提交；MiniMax 图片／视频共用桶，文本独立。短许可在实际请求前校验，不可用时延迟提交；已有外部任务的查询／下载不占新生成额度。恢复后从零补充。Redis 不保存任务状态，也不提供全局在途并发或供应商端精确 QPS 保证。 |

模型适配器只维护 DeepSeek 文本、MiniMax 图片／视频与 Mock。结构化日志和用户范围内的指标辅助排查；日志不替代数据库事实，密钥不进入快照、响应或日志。

## 版本、来源与权限

- 人物和场景是可复用资产。分镜图冻结提交时的人物／场景版本，并区分记录的来源与适配器实际发送的参考图。视频冻结首帧。换基准或换图只影响后续提交；缺失的历史来源不按现状补写。
- 出图方案持有独立修订和候选，用户确认采纳才更新主分镜。个人图片纠正从原结果的冻结输入追加新要求。普通、批次和方案出图冻结适用偏好及配方；偏好编辑或配方升级只影响后续提交。
- 个人项目按账号授权；团队项目按当前成员和角色授权。任务归属项目，产物仍经鉴权访问。团队成员离开后，原任务可继续运行，其访问权限随成员关系失效。

## Agent 执行与上下文

[Agent 运行器](../apps/api/src/main/java/com/vibestory/agent/)使用 function calling。主 Agent 可按需加载 Skill、直接调用受控业务动作或委派剧本／分镜子 Agent。子 Agent 从绑定的冻结输入读取原文或产物，通过工具提交结构化草稿，校验失败可进入下一轮修正。Skill 正文和哈希、模型请求及工具回执持久化；页面和对话共用业务服务与版本校验。分集规划沿用独立的窗口任务，图片和视频仍由媒体 Worker 处理。共享 Redis 文本准入启用时暂停新增创作模型运行。

发送给模型的内容与原始存档分开。超过预算时依次外置大工具结果、裁剪已经消费的旧工具正文、对完整原始历史生成摘要。工具协议配对、当前指令及业务引用继续保留。原始记录不会被覆盖，可按运行作用域分页回读；摘要检查点及调用也会落库，真实摘要请求丢失标为 UNKNOWN。字节阈值用于控制请求大小。详细预算、回放与验收见 [Agent 阶段记录](archive/backend-phase12.md)。

## 原型边界

团队协作限于固定角色和项目共享。产品级多租户、计费、内容审核、多供应商矩阵、高可用、移动端和成片剪辑不在当前范围内。没有独立审图／审片 Agent。历史付费样本、Mock 功能验收、固定样本 token 对照是不同证据，不能据此声称真实创作质量、成本或生产吞吐有改善。
