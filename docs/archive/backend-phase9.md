> 历史记录。当前规格和使用方式见[项目文档](../../README.md#验证与文档)。

**状态**　已实现右侧会话面板、历史与图片附件、六类子 Skill 的首批指令、单镜改写，以及拆镜后等待确认再出图的流程。自由表达可使用文本适配器生成受控指令建议。以阶段八完成后的 `f116009` 为基线。

## 已实现的会话与图片附件

顶栏提供历史和新建按钮，底部输入框可发文字、选择或粘贴图片。发送第一条消息后建立会话，刷新可恢复已选会话。聊天记录、操作回执与图片由 Flyway V13 落库，读取按登录用户隔离。每条消息最多 4 张 PNG 或 JPEG，合计不超过 5 MiB。后端验证图片内容，保存长边不超过 480 像素的预览。附件用于在对话中查看和留存，图像理解和绑定业务素材属于后续工作。

| 接口 | 用途 |
| --- | --- |
| `GET /api/agent/conversations` | 列出当前用户的历史会话 |
| `GET /api/agent/conversations/{id}` | 读取消息、附件索引和最新提案状态 |
| `POST /api/agent/conversations/{id}/messages` | 提交文字或图片，按会话和请求标识去重 |
| `GET /api/agent/conversations/images/{id}` | 读取本用户的图片预览 |

## 已实现的工作台指令

用户直接在对话框输入指令。在输入框开头输入 `/` 或 `／` 时，才从 `GET /api/agent/skills` 打开快捷菜单。继续输入可筛选示例；选择示例会填入输入框，仍需发送后才执行。后端从同一份 Java 注册表路由 Skill，默认按发送时的项目和分集执行。写入动作复用现有 Spring 服务，回执与业务写入在同一事务落库。

| Skill | 当前可执行 | 与阶段九设计的差距 |
| --- | --- | --- |
| 项目与分集 | 按项目名和集号定位，新建具名分集，设置项目风格 | 项目创建、改名、删除和分集属性编辑还需从原页面操作 |
| 故事与拆镜 | 将指令中的正文写入空集，提交首次拆镜 | 覆盖已有正文和重拆沿用原页面的确认入口。改写正文和使用附件待接入 |
| 镜头编辑与确认 | 预览单镜景别、台词缩短和画面描述，确认单镜或整集，按新描述生成单镜候选 | 运镜、时长和多镜差异待支持 |
| 参考素材 | 为具名角色或场景生成参考图，按序号选基准版本 | 上传还在资产页进行。附件指代与版本对比待支持 |
| 分镜图与视频 | 批量出已确认且缺少分镜图的镜头，单镜出图或视频，选首帧并可直接提交该镜视频 | 多镜范围表达、批量视频和更灵活的重生成待支持 |
| 进度与恢复 | 查询本集镜头失败和未知结果，查询视频首帧来源，重试本集最近批次里可重试的已知失败任务 | 对话暂以提交回执展示任务或批次 ID，实时进度沿用现有页面。未知结果的确认和恢复沿用原任务入口 |

可直接匹配的指令由 Java 注册表执行。其余文字在文本适配器中转成一条建议指令，用户可填回输入框核对。画面描述建议进入版本化改镜预览，确认时才保存或登记出图。真实路由使用 DeepSeek 兼容的单次 `tool_calls` 请求，本机 fixture 验证协议，Mock 只模拟固定样例。Redis 准入开启时，自由表达使用已注册的本地指令，因为模型建议请求尚无绑定任务 attempt 的共享许可。执行上下文来自当前页面或显式对象名称，历史用于查看前文和操作回执。

「把这集的故事拆成镜头，我确认后给没图的镜头出图」会在当前会话建立一个流程。卡片按已持久化的拆镜任务、确认决定与出图批次恢复进度。点「确认镜头并出图」，或在分镜页手动确认全部镜头后发「继续」，都绑定原拆镜结果中的镜头 ID 和正文版本。已生成分镜图的镜头会跳过。「只重试失败的」优先定位本会话同分集流程的批次，只重新排队可重试的已知失败任务。现有 Worker 执行拆镜和出图。

「把第 3 镜右边的灯改成红色，然后重新出图」在 Mock 中演示画面描述差异。点「保存并生成新候选」后，画面描述和新的单镜出图任务同事务保存。生成使用新的完整提示词，旧候选及选中状态保留。

浏览器用例覆盖新建和恢复会话、图片发送与访问隔离、正文与拆镜、镜头确认、生成场景参考图、批量出图和视频首帧追溯。后端专项覆盖跨账号拦截、只重试已知失败成员及回执重放。 [浏览器用例](../../apps/web/tests/workspace.spec.ts) · [后端回归](../../apps/api/src/test/java/com/vibestory/task/PhaseSevenIntegrationTest.java)

## 已实现的单镜改写

已登录工作台共用右侧 Agent 面板。进入一集后可输入「把第 3 镜改成近景，台词短一点」。当前使用 `apps/agent` 中的本地 Mock Skill，解析镜号和景别，并按句子或常见赘词缩短台词。后端暂存差异，刷新后可重新打开预览。此链路的模型输入和输出均在本地生成。

提案通过 Flyway V11 持久化，作用域绑定分集和实际镜头 ID。确认按预览时的版本更新，镜头写入与提案状态在同一事务提交。重复确认返回已有结果，旧提案与手动编辑冲突时提示重新预览。浏览器手动保存也带镜头版本。

| 接口 | 用途 |
| --- | --- |
| `POST /api/episodes/{episodeId}/shot-edit-proposals` | 提交指令与请求标识，返回预览 |
| `GET /api/episodes/{episodeId}/shot-edit-proposals/latest` | 恢复本集最近一份提案 |
| `POST /api/episodes/{episodeId}/shot-edit-proposals/{id}/apply` | 确认并保存 |
| `POST /api/episodes/{episodeId}/shot-edit-proposals/{id}/discard` | 放弃 |

## 目标与交互

用一个工作台对话入口操作现有创作功能。登录后可以在项目列表发起项目操作，进入项目后继续操作分集、故事、镜头、素材和生成任务。

「把第 3 镜改成近景，台词短一点」是第一条纵向验收。阶段完成时，同一入口还要能处理其他已注册的现有操作，并跑通「已有故事 → 拆镜 → 用户确认 → 批量出图」这条可等待和恢复的工作流。生成的交付边界为工作台现有的分镜图与视频片段。

### 右侧 Agent 面板

- 已登录的工作台共用一个「Agent」开关和右侧面板，覆盖项目列表和项目内各页。面板状态放在首页布局与项目布局共享的路由层，切换页面时沿用同一入口和会话。
- 宽屏采用「左侧导航 · 中间工作区 · 右侧对话」三栏。窗口较窄时右侧面板覆盖工作区，避免继续压缩分镜表格。收起时保留输入草稿和运行进度。面板复用现有主题令牌。
- 面板顶部显示新指令的默认项目和分集。执行卡显示该次操作实际绑定的对象，即使用户切到其他集，原任务也在原范围继续。镜头编辑器可用「交给 Agent」打开同一面板并带入镜头上下文。
- 对话中直接展示差异、任务进度和确认卡。点「定位到第 3 镜」跳到对应分镜，应用成功后中间工作区刷新，用户可以继续手动编辑或在右侧追问。离线演示时面板提示需要连接后端。

三栏布局与窄窗口覆盖方式参考 ArcReel。 [ArcReel 工作区布局](https://docs.arc-reel.com/dev/architecture/#studio-layout)

## 目标用户意图

子 Skill 按创作者要完成的事划分。每组工具复用对应的业务服务，覆盖范围从实际页面操作盘点。

| 用户意图 | 路由到的子 Skill | 首批指令与执行依据 |
| --- | --- | --- |
| 找到或管理项目与分集 | `workspace` | 「打开《雨夜》的第 2 集」「新建一集叫《追踪》」「把项目风格改为写实」。复用项目查询、新建、改名、风格与分集设置。项目删除先展示确认卡 |
| 准备故事并拆镜 | `story` | 「把这段文字作为第 2 集正文」「拆成镜头给我看看」。保存正文与拆解分为两个动作。已有镜头时，覆盖重拆须先展示影响并确认 |
| 查看、改写或确认镜头 | `shot` | 「把第 3 镜改成近景，台词短一点」「确认这两镜」。从本集解析稳定 ID，给出编辑差异或确认目标，沿用镜头编辑和确认服务 |
| 管理风格与参考素材 | `asset` | 「给沈夜生成一版角色图」「把第 2 版设为基准」「把我选的图片上传成雨巷参考图」。使用已有资产身份和版本服务。上传通过浏览器选文件，使用现有上传接口；模型收到的是已验证的目标和结果 ID |
| 生成分镜图与视频 | `generate` | 「给已确认但没图的镜头出图」「选第 3 镜的第 2 张图做首帧，再生成视频」。复用选图、单镜生成、整集批次与输入快照；提交前从当前状态确定本次涉及的镜头 |
| 查询进度、诊断与恢复 | `progress` | 「哪些镜头没成功」「第 3 镜视频用了哪张首帧」「只重试上次失败的」。用持久化任务、批次成员和来源记录回答。根据已有恢复条件决定能否重查、重试或提示用户处理 |

「继续」由主 Agent 识别为接续意图。它先定位当前范围内可继续的运行，重读服务端状态，再路由到相应 Skill。存在多条候选时让用户选一条。没有可继续的运行时，展示当前集的建议动作与前置条件。

模型运行配置沿用设置页的只读语义。登录与凭证由现有认证和本机配置管理。

## 主 Agent、子 Skill 和业务工具

- **主 Agent 负责目标和路由。** 每轮接收用户指令、当前项目／分集／所选对象、相关运行摘要和候选 Skill 简介。先确定目标和作用域，明确指令只执行用户要求的动作；组合指令和「继续」依据服务端返回的可执行动作推进。切换页面只更新新指令的默认范围，已有运行仍绑定它原来的对象。
- **子 Skill 负责一类操作的执行协议。** 每个 Skill 在代码库内声明 `key`、输入、所需上下文、可用工具、结构化输出和暂停条件。只在选中时加载详细规则。业务数据按需读取，例如改镜只读目标镜头和相关人物场景摘要。首版子 Skill 是主 Agent 调用的受控模块，可调用专用文本提示词，按同一运行返回结果。
- **工具负责可验证的业务动作。** Java 注册表为每项工具声明参数、结果类型、作用域和审批要求。执行器校验模型选择的工具及参数，只调允许的 Spring 服务。预览、已完成写入、业务阻塞和异步句柄分别返回，页面据此呈现。确认、前置条件和版本校验由服务端执行。
- **工作流状态由业务事实推导。** 给主 Agent 提供当前故事和镜头状态、已确认镜头、候选图与已选首帧、活跃任务、阻塞项和 `nextAction`。每次执行或恢复后重新读取。对话可以补充用户目标，实际进展以业务记录为准。

借鉴 ArcReel 的主 Agent 按服务端计划选择专门能力、结束后重读计划的做法。VibeStory 首版用子 Skill 表达这些专门能力。路由与 Skill 放在 `apps/agent` 的 Java 模块边界，随 Spring Boot 部署；`apps/api` 绑定工具到领域服务并负责持久化。模型复用 DeepSeek／Mock 配置，新增类型化工具调用契约。 [ArcReel 工作流](https://github.com/ArcReel/ArcReel/blob/110ad6b8c49afbee2782c4e92051e07d434f772a/agent_runtime_profile/.claude/skills/video-workflow/SKILL.drama.md#L42) · [工具声明 ADR](https://github.com/ArcReel/ArcReel/blob/110ad6b8c49afbee2782c4e92051e07d434f772a/docs/adr/0087-agent-toolset-single-declaration.md)

### 技术选型

ArcReel 使用 Python 版 Claude Agent SDK 承载通用工具循环、会话和子智能体，经内嵌 MCP 接入业务工具。VibeStory 选用 **Java 21 应用内执行**，以实际业务动作划分 Skill。Java 直接调用现有 Spring 服务，将业务写入与回执放在同一事务。已实现范围见上文，下表包含完整设计。 [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview) · [ArcReel 内嵌 MCP](https://github.com/ArcReel/ArcReel/blob/110ad6b8c49afbee2782c4e92051e07d434f772a/server/agent_runtime/arcreel_mcp.py)

| 层 | 阶段九选型 |
| --- | --- |
| 模型适配 | 单镜改写已接本地 Mock Skill。后续接 DeepSeek 的 OpenAI 兼容 Chat Completions，通过本机 HTTP fixture 验证 `tools` 和 `tool_calls` 契约 |
| 编排与子 Skill | 将 `apps/agent` 加入 Gradle，作为随 API 部署的 Java 模块。主 Agent 按候选 Skill 路由，选中的 Skill 加载自己的上下文、提示词和可用工具。调用业务动作通过 Java 接口交给 `apps/api`，便于用固定模型输出测试 |
| 持久化与执行 | Spring 负责权限、确认和事务，Flyway 管理 PostgreSQL 中的会话与运行。Agent 等待的是业务任务 ID 或批次 ID，实际生成沿用现有 Worker 与派发机制 |
| 前端 | 现有 React、TypeScript 和主题令牌。侧边面板按服务端返回的卡片类型渲染，先用 React Query 轮询运行进度，操作成功后刷新对应工作区。接口契约由 springdoc 生成 |

### 第一条开发链路

先用「第 3 镜改成近景，台词短一点」串起整个入口。面板提交消息，主 Agent 路由到 `shot`。Skill 通过只读工具找到第 3 镜并取当前字段，再生成结构化差异。界面显示确认卡，用户确认后才由 Spring 按镜头版本应用。用固定模型响应验证权限、事务和前端闭环。随后接入拆镜和批量出图工具，沿用同一套运行和确认机制补上等待恢复。

### 一条验收工作流

用户说「把这集的故事拆成镜头，我确认后给没图的镜头出图」。

1. 主 Agent 读取当前集的故事与镜头状态，经 `story` 提交拆镜并记录 `taskId`。若已存在镜头，先展示重拆影响；若正文为空，提示补充。
2. 拆镜完成后刷新镜头列表。面板展示待确认镜头，运行暂停。用户可以在页面手动确认，也可在对话中明确确认该批镜头。执行器按服务端当前状态复核确认结果。
3. 主 Agent 重新读取现状，把符合条件的镜头交给 `generate` 提交图片批次，记录 `batchId`。用户离开页面后仍可在原会话查看和接续。
4. 面板按镜头汇报产物和失败原因。用户说「只重试失败的」，`progress` 只从该批次定位允许重试的原任务。结果未知且已有外部任务号时按现有规则继续查询；需要重新发起外部请求时先取得明确确认。

## 作用域与确认规则

目标按显式项目／分集／镜头、当前页面选中项、同范围的前一轮对象解析。名称、序号和「这张」「刚才那一批」只用于查找，执行前由服务端固定实际 ID，核验用户、项目、集及父子关系。多个候选或引用失效时澄清。一次批量操作按当前集冻结目标集合，工具执行前复核目标和生成前置条件。

| 操作 | 执行规则 |
| --- | --- |
| 读取、导航、查询来源 | 在用户作用域内直接执行。前端按已验证对象 ID 定位 |
| 明确、低风险的操作 | 目标与参数齐备时直接执行，例如新建一集或选择指定首帧 |
| 改写镜头或正文 | 先生成差异。用户确认后应用预览所绑定的目标和版本 |
| 生成与重新生成 | 已明确授权且目标无歧义时提交；目标范围需推断、需要重生成或碰到未确认镜头时，按当前服务的前置条件展示范围或处理阻塞。提交后按任务状态报告 |
| 删除项目、覆盖重拆、未知结果下重新提交 | 单独展示具体目标与影响，再取得明确确认。「继续」只接续已授权的动作 |

确认决定与 `runId`、`stepKey`、目标集合、基准版本和参数摘要绑定。执行条件变化时重新预览。用户明确指定视频首帧时，提交事务同时核对已选图 ID，避免另一处操作换图后使用错误的首帧。对话确认与卡片按钮提交同一服务端决定。模型与工具只接收完成当前动作所需的数据，脚本、台词和用户附件内容按数据处理。

## 通用运行、等待和幂等设计

- PostgreSQL 新增会话、运行和步骤记录。会话在用户作用域内，运行记录目标、绑定对象、状态、租约和下次检查时间，步骤记录 Skill／工具、输入摘要、确认决定、工具回执及 `taskId` 或 `batchId`。项目列表上的运行可以从用户作用域开始，创建项目后再绑定业务对象。
- 运行状态区分 `READY`、`RUNNING`、`WAITING_USER`、`WAITING_TASK` 与终态。等待用户时记录原因和待处理步骤；等待生成时交还执行槽位，按持久化句柄检查。终态区分目标达成、部分完成、失败和取消。批次结束只说明成员已经结算，Agent 汇总实际成功、失败、未知与阻塞。
- 由现有 Worker 角色轮询到期的 Agent 运行，通过版本和短租约竞争推进。数据库模式和独立 API／Worker 模式采用同一套运行语义。生产任务继续使用既有任务表、Outbox 和 RabbitMQ。Agent 步骤引用任务结果，恢复时先查回执和下游状态。
- 用户消息用会话内 `requestKey` 去重。写入步骤用服务端稳定的 `stepKey` 做幂等。数据库业务写入和步骤回执在同一事务提交，提交批次沿用已有 `requestKey`，重生成沿用同一步的 nonce。重启恢复复用原执行标识。模型 HTTP 调用在事务外进行，按租约核验后保存决策。模型调用结果未知时暂停该步骤，已有写入与任务仍按回执恢复。设置每轮工具步数上限，达到上限时保留已完成步骤和当前阻塞。
- Agent 的模型调用按运行步骤记录，可先于项目创建。阶段八启用时，同凭证 Agent 调用与拆镜共享现有文本桶。实现时复用桶和短许可校验，为 Agent 步骤接入其自身的租约和准入记录；现有准入记录绑定业务任务和 attempt，二者分别保留。额度不足时记录下次执行时间，Redis 不可用时沿用故障关闭。
- 对话接口提供发消息、查询运行／步骤、提交确认或澄清。页面先轮询持久化事件与进度，刷新从会话恢复。工具响应包含受控的对象定位信息和业务状态。对话与日志的诊断字段仅暴露作用域内的必要数据。

## 首个子 Skill 闭环

从统一面板发送「把第 3 镜改成近景，台词短一点」。`shot` Skill 解析当前集的明确序号，固定 `shotId` 和镜头 `editVersion`。读取当前五个可编辑字段，生成只包含变更字段的结构化提案。台词缩短只改变台词；用户明确要求时才修改编排时长。

| 字段 | 当前 | 建议 |
| --- | --- | --- |
| 景别 | 中景 | 近景 |
| 台词 | 我想我们应该马上离开这个地方。 | 我们得马上走。 |

首版字段为画面描述、台词、景别、运镜和编排时长。复用景别／运镜枚举和时长区间，服务端拒绝越权字段、非法值、重复键和截断结果。空差异显示「没有需要应用的修改」。用户应用时提交提案决定，服务端取已保存的变更，在同一事务核对基准版本、更新镜头并保存回执。整集重拆后旧 ID 不能重新绑定到同序号的新镜头。

手动 PATCH 同样带基准版本，前端先完成待保存编辑再发起改镜。同一浏览器的防抖队列接续成功回执的版本，遇到外部冲突保留本地输入并提示刷新。应用沿用镜头确认状态，已有分镜图、视频和已提交任务保留其生成来源。后续显式生成采用新的提交快照。
