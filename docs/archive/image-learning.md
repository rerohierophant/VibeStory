# 图片纠正、用户偏好与创作配方

> 历史记录。当前规格和使用方式见[项目文档](../../README.md#验证与文档)。

个人项目的分镜表和角色 / 场景资产行提供「纠正与偏好」。用户选择已完成的生成结果，输入本次纠正，得到新的候选。记录关联原任务、本轮原话、新任务和用户评价。新候选就绪后可标记满意或不满意，满意的做法可编辑后保存为偏好或配方。

## 使用

1. 在「纠正与偏好」选择修改依据，输入画面要求，点击「按要求生成候选」。也可以在 Agent 对话里发送 `生成第1镜：雨夜冷色调`、`纠正第1镜：面容自然一点，颜色柔和一点`，或 `纠正角色《沈夜》：服装颜色柔和一点`。
2. 比较原结果和新候选，明确评价满意或不满意。Agent 支持 `满意第1镜，记住为本项目偏好`，角色和场景同样可按名称评价。生成成功与用户满意分别记录。
3. 点击「记为偏好」，核对并编辑要复用的文字规则，选择仅此素材、本项目同类图片或所有个人项目的同类图片。后续普通出图、批次和方案出图均读取适用的已启用偏好。偏好可编辑、停用、重新启用。
4. 点击「沉淀为配方」，填写名称与可复用要求。可把光线等文字参数写成 `{{lighting}}`，运行时填入。人物、场景和资产引用由本次目标提供。步骤为绑定当前素材、填写参数并生成候选、用户审阅结果。
5. 在另一项目的同类素材打开入口，选定配方版本，填写槽位并提交。「编辑为新版本」创建不可变的新版本，运行记录显示当时使用的偏好和配方。

## 保存与执行

Flyway V23 增加纠正与评价、偏好、配方及不可变配方版本。用户明确满意后才能从该结果保存偏好或沉淀配方。原始纠正保留原话，偏好是经用户确认的独立可编辑规则。素材、项目和个人范围均按图片目标类型分别生效。

图片任务继续使用原任务状态机和 Worker。提交时冻结偏好内容与版本、配方正文与参数、原任务与反馈 ID，以及已有的资产来源。对原图的纠正基于其原始生成输入追加要求并重新生成，已有适配器决定实际发送哪些资产参考图。候选通过原工作区选定为基准或首帧。新要求在提示词中排在已保存偏好和配方之后。

配方是数据库里的创作数据。Agent 通过根目录 `skills/image-learning/SKILL.md` 学习如何使用相同的受控服务，执行 Skill 继续按现有机制冻结正文与哈希。服务端验证当前项目与集、素材归属、原任务类型和完成状态。个人学习入口限定个人项目，团队图片提交使用自身原有生成输入。

生成请求和配方保存使用请求标识与输入摘要幂等。并发重放返回同一任务；生成完成后重放同一请求也返回原记录。偏好编辑与配方更新检查基准版本。原任务结果未知时沿原任务显式处理，纠正入口只接受已完成的原图。偏好停用与新配方版本只影响后续提交，历史任务保留自身快照。

## 验证入口

- `scripts/verify-all-mock.sh` 执行全量验收。用 `VERIFY_DATABASE_URL` 指向独立 PostgreSQL 16 库，集成测试用 `TEST_DATABASE_URL` 与独立 schema。
- `ImageExperienceIntegrationTest` 覆盖纠正与评价、三种偏好范围、跨账号与团队隔离、并发重放、偏好编辑、配方版本与参数、跨项目绑定、Agent 到普通出图入口。
- `apps/web/tests/image-learning.spec.ts` 覆盖 Agent 图片纠正、原图与新图比较、满意评价、个人偏好、跨项目普通出图、配方填参、新版本、停用与刷新恢复。

验收使用 Mock 图片。通过这些用例可证明反馈回流、版本与范围执行正确，视觉质量与用户返工减少需要独立的创作评价。

## 2026-11-05 验收结果

在独立 PostgreSQL 16 库中执行 `scripts/verify-all-mock.sh`，189 项后端、17 项组件和 17 项 Chrome 用例通过，类型检查、契约生成、前端构建与 HTTP 崩溃恢复通过。8 项图片经验专项覆盖原始输入回放、评价、偏好范围、重复提交、版本与跨项目执行。Chrome 专项串通 Agent 纠正、前后图比较、满意评价、个人偏好、跨项目普通出图、配方填参和新版本、停用及刷新恢复。
