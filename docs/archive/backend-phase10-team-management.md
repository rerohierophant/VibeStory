# 阶段十 · 团队管理与项目协作

> 历史记录。当前规格和使用方式见[项目文档](../../README.md#验证与文档)。

**状态：首版已实现（2026-11-04）。** 团队管理是首页左栏的独立入口，排在「设置」正上方。首版支持创建团队、站内邀请、角色管理和共享项目。个人项目继续归原账号，已有数据不会自动共享。

## 页面与操作流程

1. **首页左栏**：在 `HomeLayout` 的「设置」上方增加「团队管理」，独立路由 `/teams`。沿用现有 `NavItem` 和主题；折叠时保留图标及可访问名称。「设置」继续只读展示模型配置。
2. **团队列表**：展示我加入的团队、我的角色和待接受邀请，提供「创建团队」。邀请卡显示团队、拟授予角色和有效期，由受邀者主动接受或拒绝。
3. **团队详情**（`/teams/:teamId`）：头部显示团队名、当前角色，分「项目」「成员」两页。项目页复用现有卡片和创作工作区，支持创建团队项目；进入项目后标明团队归属，返回时回到对应团队。成员页用表格展示成员、角色、加入时间；有权限的人可邀请、调整角色、移除成员，并查看和撤销待处理邀请。
4. **项目归属**：首页「我的项目」新建个人项目；团队详情新建团队项目，弹窗明确显示归属。团队项目的剧本、分集、镜头、人物 / 场景资产、生成进度和产物供成员按权限共享。首页项目列表和首页资产库继续只聚合个人项目。团队项目首版只选内置风格，可维护项目自身的风格描述和项目资产，不引用个人自定义风格或个人项目资产。

离线演示显示「团队管理需连接后端」。连接失败时显示错误，不在本地模拟邀请、成员变更或团队项目写入。

本机演示需要两个可登录账号。沿用 `SEED_EMAIL` 和 `SEED_PASSWORD` 在本机启动时补充开发账号，已存在账号的密码不会被重置。Chrome 验收脚本会准备两组隔离的演示会话。

## 团队角色与权限

角色按团队生效。同一账号可以在不同团队有不同角色；登录身份仍由现有 Spring Security 会话提供。

| 操作 | 负责人 `OWNER` | 管理员 `ADMIN` | 成员 `MEMBER` | 只读成员 `VIEWER` |
| --- | --- | --- | --- | --- |
| 查看团队、成员、项目、任务进度与产物 | ✓ | ✓ | ✓ | ✓ |
| 创建或编辑项目、编辑剧本 / 分镜、管理项目资产、提交 / 重试 / 恢复生成 | ✓ | ✓ | ✓ | — |
| 查看项目内生成诊断 | ✓ | ✓ | — | — |
| 重命名团队、删除团队项目 | ✓ | ✓ | — | — |
| 邀请、改角色或移除普通成员 / 只读成员 | ✓ | ✓ | — | — |
| 邀请管理员、升降或移除管理员 | ✓ | — | — | — |
| 主动退出团队 | — | ✓ | ✓ | ✓ |

团队创建者是唯一负责人，首版不提供负责人转让或团队删除。管理员不能赋予管理员或负责人权限，也不能操作其他管理员；移除成员、降权、删除项目需显示影响并确认。前端按服务端能力字段呈现按钮，后端仍独立执行校验。团队外用户猜测资源 ID 得到 `404`，团队内缺少操作权限得到 `403`；重复或过期状态按契约返回现有结果或 `409`。

## Java 后端设计

原有子表外键、Worker 和媒体路径使用项目的 `user_id`。本阶段把「谁在操作」与「资源归哪里」分开。HTTP 入口用 [ProjectAccess](../../apps/api/src/main/java/com/vibestory/project/ProjectAccess.java) 从真实资源回查项目，再校验当前成员权限。业务服务和 Worker 继续用原项目标识校验归属。

| 数据 | 设计 |
| --- | --- |
| `team`、`team_member` | 团队 ID、名称、创建时间；成员表以 `(team_id, user_id)` 唯一，保存角色、加入时间。外键约束团队和账号，部分唯一索引限制至多一个 `OWNER`；建队事务同时写入负责人，成员变更禁止移除或降级负责人。 |
| `team_invitation` | 保存团队、规范化邮箱、角色、邀请人、有效期和处理状态，默认有效期 7 天。同一团队同一邮箱最多一条待处理邀请；重发前先将到期邀请置为过期。邀请只在站内显示，不发送邮件、不开放账号搜索或新增注册；只有会话邮箱匹配的登录人能接受或拒绝。 |
| `project.team_id` | 可空外键。为空时由原 `user_id` 决定个人归属；有值时团队成员关系决定访问权限。新增团队项目用创建账号初始化原 `user_id`，随后固定作为旧子表关联和媒体路径的内部标识；创建人退出团队后，项目仍归团队。首版不转移项目，不重写旧外键、任务快照或媒体路径。 |
| 操作记录 | PostgreSQL 记录建队、邀请处理、角色变化、移除、退出和团队项目创建 / 删除，含操作者、团队、目标、动作、时间及必要的角色前后值。同业务写入提交；新团队生成任务、批次另外记实际提交人，任务复用时不覆盖原提交人。 |

- 在 `apps/api` 新增 `team` 业务包，使用 Spring MVC、Bean Validation 和 Spring Security 现有会话 / CSRF。简单 CRUD 用 Spring Data JPA；成员关系校验、列表联查及并发条件更新用 jOOQ。角色使用固定枚举，由服务层映射到具体操作，数据库是成员关系的事实来源。
- 个人入口继续验证登录人等于个人项目所有者且 `team_id IS NULL`。团队资源先从服务端查真实父项目，再以登录人的当前成员关系授权；不能相信前端传的归属，也不能把创建者 ID 当成登录人去调用旧服务。授权后的内部查询才可用项目固定标识校验子表和媒体，所有请求仍保留真实操作者。
- 覆盖列表、详情、项目统计、分集、镜头、版本、任务、批次、诊断和媒体入口。嵌套路由核对所有父子关系；仅有子资源 ID 的入口先反查父项目。个人任务统计必须排除团队项目；团队诊断只返回项目内必要的错误和状态，不返回供应商原始响应。团队媒体读取和视频 Range 请求均重新授权，通过现有受保护端点返回，设置 `Cache-Control: private, no-store`。
- 所有成员变更用显式事务，同团队的管理写入按团队行串行。邀请接受重新检查待处理状态、期限、账号邮箱及邀请人当前可授予的角色；新增成员与更新邀请同事务，同账号重放接受不再新增成员，也不能用旧邀请重新加入。邀请人失去相应权限后撤销其仍待处理的邀请。
- 团队业务写入在事务内锁定并检查操作者的成员记录，再沿用项目及子资源锁顺序。移除和降权与该授权检查互斥：已经提交的操作保留，撤权先提交则后续写入失败。共享编辑对项目字段、剧本与镜头采用提交时的版本检查，冲突返回 `409`，页面保留本地草稿并提示刷新比较。

### API

| 接口 | 用途 |
| --- | --- |
| `GET /api/teams`、`POST /api/teams`、`GET/PATCH /api/teams/{teamId}` | 我的团队、创建、详情、改名；返回我的角色和可操作项 |
| `GET /api/teams/{teamId}/members`、`PATCH/DELETE /api/teams/{teamId}/members/{userId}` | 成员列表、改角色、移除；非负责人通过删除自己的成员记录退出 |
| `GET/POST /api/teams/{teamId}/invitations`、`DELETE /api/teams/{teamId}/invitations/{id}` | 管理可见的邀请、创建和撤销 |
| `GET /api/me/team-invitations`、`POST /api/me/team-invitations/{id}/{accept|decline}` | 只处理发给当前会话邮箱的邀请 |
| `GET/POST /api/teams/{teamId}/projects` | 团队内列表与新建；既有项目和子资源详情、写入端点按真实项目归属授权 |

OpenAPI 由 springdoc 导出，前端类型由 `packages/contracts` 生成。项目工作区按项目 ID 单独加载，支持从链接直接进入，服务端返回团队归属和操作权限。查询与待保存草稿按登录账号及团队或项目区分。成员在已打开的项目页面被移除后，下次请求即失去访问，页面轮询发现后清除团队缓存和待提交草稿并返回团队列表；已下载的文件无法收回。

### 任务、媒体和 Agent 边界

- 提交生成时检查操作权限；已经提交的任务属于项目，提交人退出或被移除后仍按原输入、租约和 Outbox 继续执行，其他有权限的成员可查看结果。提交者本人不能再查询、下载、重试或恢复。Worker 按持久化任务和项目归属执行，无需查询提交人的当前角色。既有 RabbitMQ / Redis 机制继续复用，首版不引入团队配额。
- 同一团队项目里，重复提交沿用项目内的任务去重与批次幂等；两个成员提交同一活跃输入不应各跑一份。批次请求键绑定项目 / 分集及冻结参数，等价重放返回原批次，异参冲突；主动重生成仍由显式标识区分。禁止引用其他团队或个人项目的资产版本与首帧。
- 阶段九 Agent 首版继续只访问个人项目：团队项目内不提供 Agent 操作入口；后端也拒绝手工传入的团队项目上下文或资源 ID。Agent 搜索、提案、回执和会话历史不纳入团队数据。以后开放时，工具执行和回执重放都要重新授权。

## 实施顺序与验收

| 里程碑 | 完成条件 |
| --- | --- |
| 10A · 团队管理 | Flyway 增量迁移、创建团队、站内邀请、成员列表、改角色、移除 / 退出；左栏入口和页面闭环 |
| 10B · 项目协作 | 团队建项目，成员按权限进入现有工作区；覆盖项目、资产、版本、任务、媒体及拒绝访问的入口，保留个人项目兼容；通过权限与并发验收后开放共享项目入口 |
| 10C · 验收收尾 | 导出契约、完成双账号 Chrome 演示和 Mock 生成，记录实际结果及限制 |

验收使用隔离 PostgreSQL 16 和 Chrome，生成全部使用 Mock。团队专项后端测试位于 [TeamIntegrationTest](../../apps/api/src/test/java/com/vibestory/task/TeamIntegrationTest.java)，浏览器双账号流程位于 [workspace.spec.ts](../../apps/web/tests/workspace.spec.ts)。已覆盖邀请接受竞争、角色与越权、旧版本冲突、任务复用、项目创建者被移除后任务继续、以及图像与视频 Range 的访问变化。

数据库模式整套回归通过：148 项后端、17 项组件、12 项 Chrome，以及 OpenAPI 导出、前端构建和 HTTP 崩溃恢复。摘要位于 `data/verification/phase6-13f49874d7/summary.json`。

真实 RabbitMQ 专项另用独立 API 和 Worker 验证。成员提交拆镜后被移除，Worker 启动后从队列完成原任务，数据库只有一次成功 attempt；团队负责人随后可以提交分镜出图并读取产物，已移除的创建者读取任务和图片均返回 404。Mock 专项记录位于 `data/verification/team-mq-8716012e03/summary.json`。

迁移专项先在 Flyway V14 保存个人项目、分集、镜头及选定图片，再启动当前版本。原账号仍可查看个人项目和相同的图片内容，项目未被加入团队。记录位于 `data/verification/team-upgrade-1b4f739d9e/summary.json`。

后续回归保留以下场景：

1. **完整协作**：账号 A 建队并邀请 B；B 接受后在团队项目编辑剧本、生成分镜，A 查看同一进度和产物；双方的个人项目和个人资产仍隔离。
2. **权限矩阵**：用管理员、成员、只读成员和团队外账号发请求。只读成员可看图和视频、不能写；管理员无法提权或移除同级；用别的团队的项目、镜头、任务、版本、媒体链接和首帧 ID 验证拒绝，覆盖视频 Range 和伪造 Agent 上下文。
3. **邀请和并发**：错误账号、过期或撤销邀请不能加入；并发接受只产生一条成员记录；并发降权 / 移除与写入按事务先后生效；两个编辑者的旧版本不能覆盖较新的剧本或镜头。
4. **撤权与恢复**：B 提交 Mock 任务后被移除，原任务继续完成，A 可查可下载，B 已打开的工作区和旧直链不能继续读写；A、B 对同一活跃输入提交时核对实际 Mock 调用与任务去重结果。
5. **兼容性**：在已有个人项目和历史媒体的数据库上迁移，核对项目归属、版本来源、播放、生成与旧入口；切账号、退出团队和刷新时无串数据，离线入口不产生本地团队写入。

首版范围止于团队级固定角色和项目共享。实时同屏编辑、项目级 ACL、部门树、自定义角色、系统管理后台、SSO、计费与产品级多租户运维不排入本阶段。
