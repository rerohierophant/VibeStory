# 阶段十一 · 创作方案分支与并行生成

> 历史记录。当前规格和使用方式见[项目文档](../../README.md#验证与文档)。

**历史功能，已随 V28 移除。** 本文记录当时的范围与 Mock 验收。当前出图方式见[创作流程](../workflow.md#agent-对话)。

## 用户场景与范围

本阶段限定为分镜文生图。用户选中同一集的一镜或一组已确认镜头，从同一个基准版本创建多套方案，分别调整画面描述、景别或运镜。例如同一镜雨夜追逐可以分别用远景交代巷道和用近景突出脚步，两套参数各自生成分镜图。用户并排比较后，明确采纳单镜或一组镜头的参数和对应分镜图。修改一个方案里的部分镜头时，只重出这些镜头，其余分镜图继续引用已有结果。

方案使用固定的镜头集合和现有分镜出图入口。人物与场景沿用已选参考版本的来源记录，产物归属到对应镜头和方案修订。所有生成验收使用 Mock。

本场景让多 Worker 并发、共享提交限流、输入快照和幂等服务于具体需求：同时尝试多个创作方向，结果可区分、可比较、可采纳。模型生成可以并行，结果归属与采纳必须有确定的事务语义。

## 已实现入口

- 从「分镜出图方案」新建并提交。每集最多保留 6 个活动方案，每次可选择 1 至 12 个已确认镜头。对比表按镜头排列，展示各方案的出图参数、候选图、来源与任务状态。
- 从对比表选中一套方案中的一镜或多镜，预览当前值与方案值，再确认采纳。采纳同时更新镜头参数和选定图。局部重出时，仅选中的镜头提交新任务，其余沿用原任务及结果。
- Agent 支持「给第 3 镜创建近景出图方案《雨巷》」「查看出图方案」「把出图方案《雨巷》的第 3 镜改为特写并重出」「预览采纳出图方案《雨巷》的第 3 镜」。预览卡需显式确认，采纳后可在原对话回查。
- 团队项目的方案页使用项目授权。只读成员可比较方案，有编辑权限的成员可提交与采纳。Agent 入口沿用个人项目范围。

## 数据与执行约定

### 1. 独立的方案修订

- 方案归属分集，保存创建人、稳定 ID、名称和固定镜头集合。不可变修订保存每镜的画面描述、景别、运镜及任务引用。图片任务快照记录提交时的风格、提示词和参考版本。
- 局部重出创建新修订，所选镜头各创建一个新任务。重试失败沿用原任务和输入，并新增 attempt。不同方案即使参数相同，也各有任务身份。
- 给任务和产物增加可查询、受约束的方案成员关联，保留现有镜头身份及原工作区入口。分镜页的普通出图进度按原入口查询，方案页按修订成员查询。已采纳的方案产物进入主分镜候选列表。
- 同一提交请求标识重放返回原修订，换参数返回冲突。任务输入签名包含方案修订和冻结参数，方案任务继续沿用 `IMAGE` 类型。

### 2. 从快照生成并隔离结果

- 新增从已验证方案快照构造分镜文生图输入的业务入口，复用现有图片 Provider、任务表和执行器。
- 核验用户对项目的访问权限，以及分集、镜头、方案修订和参考版本的归属。提交时冻结实际出图参数和人物 / 场景参考版本。
- 任务和 Outbox 同事务登记，RabbitMQ 派发给现有 Worker。启用准入后，方案任务使用现有共享图片提交额度。
- 方案结果写入对应修订的镜头成员，主工作区选图由显式采纳更新。写回校验任务租约、版本和方案修订归属，避免迟到结果覆盖新选择。
- 按镜头展示成功、失败、UNKNOWN、阻塞与暂停。局部重试只提交当前方案当前轮次中允许重试的成员。结果未知时沿用现有的明确确认规则。

### 3. 比较、采纳与局部重生成

- 页面提供按镜头排列的方案对比，显示参数差异、产物及任务状态。先支持单镜采纳，再支持对选定镜头集合一次采纳；采纳前展示具体字段与产物差异。
- 采纳回执记录操作者、方案修订、分镜图 ID 和预览时主工作区的镜头版本及已选图。在一个事务内检查所有目标后更新字段与选定图，任一目标冲突则整组回滚并提示重新比较。重复确认返回既有回执。
- 局部修改创建新方案修订，只为用户选定的修改项提交新任务。未选择的成员继续引用原任务，保留原输入和产物来源。新出图任务冻结提交当时的人物和场景参考版本。
- 主工作区或基准资产后来变化，不自动使已有方案产物失效，不自动取消或重做历史产物。方案基准与当前主工作区存在差异时展示差异，是否采纳由用户决定。
- 首版方案只归档，不物理删除共享产物；已有重拆 / 删除路径必须识别被引用的媒体。活跃方案存在时阻止覆盖重拆，先归档并明确确认影响；实际移除镜头时同事务撤销相关方案引用与活跃任务，媒体清理须确认无剩余引用。仅归档不能提前解除媒体保护。

## 验收

- 后端专项覆盖乱序完成、未采纳图隔离、请求并发重放、局部复用、采纳冲突整组回滚、归档前禁止覆盖重拆、团队角色与撤权，以及 Agent 工具调用。
- Chrome 用例覆盖方案创建与对比、局部重出、刷新恢复、旧预览拒绝采纳，以及 Agent 采纳后的对话回查。
- 真实 PostgreSQL、RabbitMQ、Redis 和独立 Worker 环境中提交两套双镜方案。Redis 停机期间四个任务均未创建 attempt。恢复后注入两条重复 MQ 通知，再终止正在执行的 Worker。四个任务最终均成功，只有被中断任务有两次 attempt。四张图各自归属方案，主分镜选图仍为空。图片全部由 Mock 生成。
