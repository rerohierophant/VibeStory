# 实现路线

状态：后端与联调均为待实现计划；**前端页面已实现（本地状态）**。产品定义见 [product.md](product.md)，技术方案见 [tech-design.md](tech-design.md)。

本版路线已按页面结构重排：**集是生产单位**，所以「分集」从阶段二就出现，而不是等到镜头阶段才补一个字段。凡页面没有入口的功能（导出、用量、手工补镜、拖拽排序）不在本路线中。

## 排序原则

不按日历排期，按**依赖关系**排序。三条规则：

1. **先通一条链路，再往两侧扩。** 任何一个阶段结束时，从浏览器点得通、看得见。
2. **每一步的产物是下一步的输入。** 上一步没有的东西，不在下一步补。
3. **页面已经给出的交互，后端必须能承载。** 不允许出现「页面能点、后端没接口」的悬空状态。

标记说明：**[必做]** 缺失即链路不通；**[推荐]** 显著提升完成度，时间允许就做；**[可选]** 有余力再做，砍掉不影响演示。

## 前端现状（已完成）

在写后端之前，先把页面事实固定下来，后续阶段都以它为验收对象：

- 工程：React 19 + TypeScript + Vite 6 + Tailwind CSS v4，`design/theme.js` 令牌注入。
- 路由：`/login`、`/`、`/assets`、`/settings`、`/projects/:id`、`/projects/:id/episodes`、`/projects/:id/episodes/:episodeId/:tab?`、`/projects/:id/characters`、`/projects/:id/scenes`。
- 页面：项目列表 / 新建 / 重命名 / 删除、项目概览、分集卡片、工作区三 Tab（故事 / 分镜 / 视频）、项目资产库、全局资产库、设置。
- 数据：`localStorage`（键 `vibestory.state.v2`）+ Mock 拆解器（`lib/splitter.ts`）+ 定时器模拟生成时序。
- 缺口：没有后端、没有真实上传、没有导出、没有用量、镜头不能增删排序。

前端这部分的验收：`npm run build` 通过；刷新后数据不丢；三 Tab 的禁用与回退符合 `EpisodeWorkspacePage`。

## 阶段一：后端骨架与最小纵向链路

**为什么排第一**：状态机、任务表、幂等这三件事决定了后面所有交互形态。先在前端之前定下来，后面改的是 UI，不是数据模型。

### 1.1 工程骨架 **[必做]**

- 安装 JDK 21（本机尚未安装），初始化 Spring Boot 3 + Gradle 工程。
- Flyway 迁移 `V1__init.sql`：`user`、`project`。
- 统一错误响应（ProblemDetail）、参数校验、springdoc OpenAPI 可访问。
- 本地 `docker-compose.yml`：PostgreSQL 16；`application-local.yml` 与 `.env.example`。集成测试用 Testcontainers 起真实 PostgreSQL，不用 H2。

### 1.2 账号与作用域 **[必做]**

- 登录 / 登出 / `GET /api/me`；BCrypt 存密码；注册接口留作种子数据，不对外暴露页面。
- `ScopeGuard`：`userId → projectId → episodeId → shotId` 逐层校验，越权返回 404。
- 一条集成测试：A 访问 B 的项目返回 404。

### 1.3 任务机制 **[必做]**

- `V2__task.sql`：`task`、`task_attempt`，含活跃任务部分唯一索引与 `episode_id`。
- 租约轮询 Worker：`FOR UPDATE SKIP LOCKED` 领取、90 秒租约、30 秒续约、乐观锁。
- `input_signature` 规范化函数 + 单元测试（空格、换行、key 顺序、浮点精度、nonce）。
- `MockVideoProvider`：固定 3 秒占位视频，可配置延迟与失败率。

### 1.4 最小全链路 **[必做]**

- `POST /api/projects` → `POST /api/projects/{id}/episodes` → `POST /api/shots/{id}/video-tasks`（先用手工插入的占位镜头）→ Worker 执行 → `GET /api/tasks/{id}`。
- 不碰前端，用 HTTP 文件或 curl 走通。

**阶段验收**

- 全链路可跑通，任务状态按 `QUEUED → RUNNING → SUCCEEDED` 流转，API 投影为「产物就绪」。
- Worker 中途被杀，租约到期后任务被重新领取，`attempt` 递增。
- 同一输入连续提交 10 次，只有一条活跃任务、一条进行中尝试。
- 跨用户访问返回 404。

**刻意不做**：前端联调、真实供应商、资产、Agent。

## 阶段二：项目、分集与故事

**为什么是第二**：集是后面所有产物的容器。先让「项目 → 分集 → 正文」这条骨架可持久化，拆解与生成才有地方落。

### 2.1 项目 **[必做]**

- `project`：名称、画面类型（六种枚举）、风格描述。
- 列表、搜索、新建、重命名、删除；删除级联清理分集、镜头、资产与媒体。
- 概览统计接口：分集数、镜头数、已确认数、已选定分镜图数、已出片数。

### 2.2 分集 **[必做]**

- `V3__episode.sql`：`episode(project_id, index, title, summary, story_content, breakdown_state)`。
- 新建一集（`index` 取当前最大 + 1）、改集名、改梗概。
- 集内统计：镜头数、已确认、有图、有视频。

### 2.3 正文 **[必做]**

- `PUT /api/episodes/{id}/story`：整体替换正文，保留唯一原文。
- 大小与编码校验；`.txt` / `.md` 由前端读取后按文本提交，后端不解析文件。
- 修改正文把 `breakdown_state` 从 `DONE` 回退为 `IDLE`，但不删镜头。

**阶段验收**

- 建项目 → 建三集 → 每集各写一段正文 → 刷新后完整可读。
- 集 `index` 连续且唯一；删除中间一集不影响其余集的 `index` 展示。
- 跨用户访问集与正文返回 404。

**刻意不做**：拆解、资产、生成。

## 阶段三：拆解与镜头清单

**为什么是第三**：正文必须变成结构，后面所有生成才有依附对象。这是第一个「AI 真的在工作」的地方。

### 3.1 镜头模型 **[必做]**

- `V4__shot.sql`：`shot(episode_id, seq, scene_name, shot_size, camera_move, description, dialogue, duration_ms, status)`，唯一约束 `(episode_id, seq)`。
- 状态机：`DRAFT ⇄ CONFIRMED`，取消确认是对外接口。
- `DRAFT` 提交生成返回 409；`CONFIRMED` 仍可改字段、切图、重做视频，不设额外写保护。

### 3.2 拆解任务 **[必做]**

- `TextProvider` 接口 + `MockTextProvider`：把前端 `lib/splitter.ts` 的规则原样移植（按空行分段、句末切分、引出语并句、场景词表匹配、台词判断景别），保证同一正文拆出同一结果。
- 拆解结果写入镜头，标记 `DRAFT`；同一份正文重复触发复用未完成任务。
- 重新拆解在同一事务内清空该集旧镜头与媒体，任务与尝试保留。

### 3.3 镜头编辑与确认 **[必做]**

- `PATCH /api/shots/{id}`：描述、台词、景别、运镜、场景名、时长。
- 单镜确认 / 取消确认、整集确认。
- 编辑结果刷新不丢。

### 3.4 资产名称解析 **[必做]**

- 拆解产出的 `scene_name` / `character_names` 按项目内名称解析为资产，未命中则建卡。
- 名称在项目内唯一（`lower(name)`），重复只建一张卡。

### 3.5 真实文本模型接入 **[推荐]**

- 一个真实 `TextProvider` 实现，输出严格的 JSON 结构，解析失败要能看出原始响应。
- 通过配置开关切换，默认仍是 Mock。

**阶段验收**

- 一段 800 字正文拆出 ≥10 个可编辑镜头。
- 同一正文重复触发拆解，不产生第二条活跃任务；重新拆解后旧镜头被清理。
- 未确认镜头无法提交生成，且接口返回 409 而不是静默忽略。
- 已确认镜头改字段成功；取消确认后回到待确认，仍不可提交生成。
- 拆解出的角色名只建一张卡。

**刻意不做**：分镜图、视频、资产版本。

## 阶段四：资产库与分镜图

**为什么是第四**：有了镜头才有「引用谁」的问题；资产版本和引用快照必须在第一次生成之前就位，否则一致性设计无从谈起。

### 4.1 资产模型 **[必做]**

- `V5__asset.sql`：`character`、`scene_asset`、`asset_version`（部分唯一索引 `WHERE is_selected`）、`asset_ref`。
- 版本来源分 `uploaded` / `generated`；同一资产只能有一个 `is_selected`。

### 4.2 资产接口 **[必做]**

- 项目内角色库 / 场景库列表；全局资产库（跨项目）列表，带项目名与使用统计。
- 新增版本（生成 / 上传）、切换选定版本。
- 使用统计：出现于多少个镜头、哪些集；按名称聚合，与页面展示一致。

### 4.3 分镜图生成 **[必做]**

- `V6__media.sql`：`shot_image(shot_id, label, storage_key, status, selected, input_snapshot)`。
- `ImageProvider` + `MockImageProvider`：按 `input_signature` 生成确定性占位图。
- 生成请求带上引用的角色 / 场景当前选定版本，写入 `input_snapshot`。
- 第一张 `READY` 自动 `selected`；已确认镜头同样可以切图。

### 4.4 分镜接口与轮询 **[必做]**

- `GET /api/episodes/{id}/shots?filter=all|todo|stale|draft`：一次返回该集镜头、候选、视频摘要。
- `GET /api/episodes/{id}/shots?taskActive=true`：按集轮询的收敛点，3 秒一次，页面失焦停止。
- 响应形状直接对齐 `types.ts` 的 `Shot`，减少前端改造。

### 4.5 真实文生图接入 **[推荐]**

- 一个真实 `ImageProvider`，支持参考图输入；能力不足时降级为纯文生图并在 UI 标注。

**阶段验收**

- 生成分镜图时确实带上引用的资产版本（可从 `input_snapshot` 断言）。
- 换角色基准版本后，已生成的图可识别为「基于旧版本」。
- 单镜重生成不影响其他镜头；第一张图自动选定，后续候选可手动切换。
- 同一镜头同一输入重复提交复用未完成任务；点「再生成一版」产生新任务。

## 阶段五：图生视频与陈旧标记

**为什么是第五**：视频是链路里最贵的产物，只有图和资产都稳定后才值得接。此时才能实现「图变则视频失效」这一核心价值。

### 5.1 视频生成 **[必做]**

- `video(shot_id, source_image_id, source_image_version, status, attempt_count, error_message, stale)`。
- 以提交时选定的分镜图为首帧；Worker 记录提交时的首帧，而不是结束时的最新图。
- 播放、失败原因、重试；`attempt_count` 与 `task_attempt` 对账。

### 5.2 陈旧双向同步 **[必做]**

- 选定新图：同事务内把 `READY` 视频置 `stale = true`。
- **切回原图：同事务内复位 `stale = false`**。
- 旧视频不删除，`source_image_version` 可回查；视频页「陈旧」筛选与计数读这一列。

### 5.3 视频接口 **[必做]**

- `GET /api/episodes/{id}/shots` 的视频摘要字段满足五种筛选：全部 / 已生成 / 未生成 / 失败 / 陈旧。
- 只返回已确认镜头的出片能力；未确认或未选图时接口拒绝并给出可读原因。
- 失败与「结果未知」分开：可重试的失败允许重试；未知要求用户显式确认。

### 5.4 四种提交情况 **[必做]**

- 重复提交复用任务；主动重新生成走 `regenerate_nonce`；可重试失败新建 attempt；外部结果未知置 `UNKNOWN` 并交给用户决策。

### 5.5 批量操作 **[推荐]**

- 整集确认已有页面入口，必须落到接口；逐条走状态机，不允许绕过。

**阶段验收**

- 连续点提交只产出一段视频。
- 失败后可重试，attempt 记录清晰，页面「尝试 N 次」与后端一致。
- 换图后旧视频被标记而非删除；切回原图陈旧解除。
- 供应商超时不会被误判为成功，页面显示「结果未知」。

## 阶段六：前端联调与收尾

**为什么最后**：页面已经成型，联调是把 localStorage 换成 API，同时验证前面五个阶段的设计是否真的能被页面消费。

### 6.1 数据层替换 **[必做]**

- 引入 TanStack Query；`StoreProvider` 的动作逐一替换为 API 调用，组件形状不变。
- 写后失效 `episodes` / `shots` 两个键；轮询按集收敛。
- 错误态：409（未确认）、404（越权或不存在）、`UNKNOWN`（结果未知）分别有明确文案。
- 离线演示模式保留：没有 API 时自动回落到本地状态，用于录屏。

### 6.2 观测与日志 **[必做]**

- 结构化日志：任务领取、attempt 起止、陈旧置位、作用域拒绝。
- 基础指标：任务排队时长、执行时长、失败率。

### 6.3 测试补全与故障注入 **[必做]**

- Testcontainers 集成测试：作用域、唯一索引、任务并发领取、重新拆解覆盖。
- 故障注入：Worker 崩溃、供应商超时、重复请求、切回原图。
- 前端组件测试：筛选计数、前置条件文案、空态。

### 6.4 演示与文档 **[必做]**

- 从登录到出片走一遍并录屏。
- README 每条能力对应实现与验证方式；区分「页面已实现（本地）」「后端已实现」「已测试」「真实供应商验证」。
- 文档与页面不一致时，以页面为准并同步修订。

### 6.5 真实供应商验证 **[可选]**

- 接入一个真实视频供应商，记录能力描述、恢复边界与单次成本，在文档中如实标注验证范围。

**阶段验收**

- 全流程可复现演示：登录 → 建项目 → 建集 → 写正文 → 拆解 → 确认 → 出图 → 选择首帧 → 出片。
- 测试覆盖六条“看起来对但会错”的地方（见 tech-design §12）。
- 简历指标均有测试记录或可复现演示支撑。

## 不做（本版本）

成片剪辑、调色、混音、字幕轨、数字人、多集串行批量生产、多人协作与权限、模板化批量投放、移动端、计费与支付。

以及**页面没有入口、因此本期不进后端**的四项：

- 镜头的手工补镜、删除、拖拽排序。
- 分镜包导出。
- 用量 / 费用统计与每日额度。
- 项目封面图上传（封面由画面类型派生）。

判断一个需求该不该做，用一句话：它是否服务于「任务状态机、幂等、作用域隔离、版本与陈旧判定」。不服务于这四件事、页面又没有入口的产品功能，一律不做。

## 如果必须压缩

按以下顺序砍，链路仍然完整：

1. 5.5 批量操作、4.5 真实文生图、3.5 真实文本模型 → 全 Mock 演示。
2. 6.2 观测与日志 → 只保留结构化日志。
3. 6.5 真实供应商验证。
4. 4.2 中的使用统计聚合（数据模型保留）。

不能砍的是阶段一至阶段五的 **[必做]** 项，以及 6.1 数据层替换与 6.4 演示——没有联调，页面就永远只是本地演示；没有演示，工作台就没有交付物。
